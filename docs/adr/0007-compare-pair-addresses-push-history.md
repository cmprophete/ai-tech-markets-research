# Compare pair addresses add history steps, the one exception to rewriting the address

**Status:** accepted (2026-11-24; the owner, "Yes, go ahead", to giving each comparison its own address "for sharing and the browser's Back"). Amends the router's rule that the address is only ever rewritten (`src/js/40-router.js`).

**Context.** The site's address bar follows navigation with `replaceState` and never adds a history step (the router's header comment: "no history spam"): a tab, a section, a place and a dialog are each an address, the browser's Back leaves the site, and one `hashchange` listener re-applies a pasted link. The Landscape's Compare view had no address at all (the Landscape's switch is not routed, and `#policy` was the whole tab), and its own Back button walked a list of pairs kept in memory, 30 deep, which a reload emptied and the browser knew nothing of. The owner asked for an address for each comparison, "for sharing and the browser's Back". The page is also embedded as an iframe in the owner's WordPress site. Checked on 2026-11-24 in Chromium, with a scratch page that holds a page in an iframe: the frame's history steps join the top window's (its history length went from 2 to 4 after two steps), the top window's Back moves the frame back one step and fires `popstate` and then `hashchange` inside it, with each step's own state restored, and the top window's own address never changed.

**Decision.**

- The pair on screen is the address: `#compare/<policy-a>/<policy-b>`, the policies' ids as they are (lower-case letters, digits and hyphens, so nothing is escaped), A on the left; nothing is sorted, so a shared link shows what the sender saw. `#compare` is the view on the pair it opens with. An address that does not name two policies on the page (an id that is no policy, one id alone, a policy the Sheet has archived) opens Compare on that first pair and is rewritten to say so, as `#enforcement/<place>` and `#brief/<section>` do; the ids are looked up in `POLICY_DATA` and nothing else from the address reaches the page.
- A change of the pair the reader makes (a menu, a competing-pairs pill, Previous or Next, a sample: everything that goes through `polCmpGo`) adds ONE history step with `pushState`. Everything else keeps the rule: opening a link, the browser's Back and Forward, the Landscape's switch, the tabs and the policy dialog rewrite the address and add nothing. Compare is the only view whose changes are steps.
- The step remembers the pair before it in `history.state`, as `{ polCmp: { prev: [a, b] } }`. The Back pill is the browser's Back limited to the pairs: it is on only when the step the page is on has such a pair, it names it, and pressing it calls `history.back()`, so the pairs have one timeline and not two. The in-memory list is gone. `setHash` and the router's Compare rewrite keep the step's state (`replaceState(history.state, ...)`, where they wrote `null`), so a tab, the switch or a dialog rewriting the address does not wipe it.
- The router applies a Compare address through `polCmpSet`, which draws the pair and never writes the address or adds a step. The Landscape's switch is exposed as `polShowView` (it was a closure inside `buildPolicyView`) so the router can put the Landscape on Compare, and `#policy` puts it on All, so the address says what is on screen.
- A **Copy link** pill beside Back copies `appURL('compare/<a>/<b>')`, the page's own location plus the pair, built as the policy dialog's Copy link is.

**Consequences.**

- Back and Forward walk through the pairs on the standalone page and in the embed, and a reload keeps the step's memory, because `history.state` survives it.
- The embed's own address does not follow the pair: the parent page's address belongs to the parent, whatever the frame does. That is why Copy link exists. Inside the frame the copied link is the dashboard's own address, which opens it on the pair; for a link to the WordPress page itself to open the right pair, the WordPress page would have to pass its own `#compare/...` into the frame, which is a change on the WordPress side and not made here.
- A reader who changed the pair ten times needs ten presses of Back to leave Compare. That is what a view whose changes are steps does, and the switch, the tabs and the dialog stay out of the history, so it is the only place it happens. Previous and Next add a step each (stepping through the 29 recorded pairs adds 29), as the in-page Back it replaces undid each of them. If that proves too many, stepping could replace instead of push, at the price of Back skipping the stepping.
- The step is added inside `try`/`catch`: Safari limits how often a page may add one, and a refusal must cost only the address and Back, never the comparison.
- With a policy dialog open, the browser's Back moves the pair behind it; the router has never closed a dialog on a route change.
- Only Chromium and the jsdom tests were run. Firefox and Safari should fire `hashchange` on Back across such steps, as the HTML standard says; if one does not, a `popstate` listener doing the same redraw (a no-op when the pair is already on screen) is the fallback.
- Done later the same day: an address for the Links view, the same few lines ([0009](0009-links-policy-addresses.md)).
- The tests drive Back and Forward with `history.back()` and `history.forward()` and wait for them (jsdom finishes them a moment later), so the Compare checks that need that run as one async group at the end of `tests/interactions.js` (`compareAddressTests`), as the other async groups do. `tests/routes.js` pins three new routes (`#compare`, a pair, and a pair that is not two policies).

**Update (2026-11-24, later the same day):** the row of competing-pair pills and the Previous and Next walk through the pairs that work well together are gone (the owner's request), and the consequence above that Previous and Next add a step each no longer applies. A Randomize button and a Refresh button (back to the pair the view opens on) took their place beside Back and Copy link; each is a change of the pair through `polCmpGo`, so each adds one step, like a menu or a sample. The two menus and the pills moved from a bar inside the view onto the switch's row, with Copy Draft and Print added ([0010](0010-landscape-switch-row-holds-view-controls.md)).

# Legislation sources

Where the bills on the Legislation tab (in the Government action nav group) come from, how the list is made, and how to refresh it. The data file is
`data/legislation-bills.js`, generated by [`tools/legislation.py`](../tools/legislation.py) from what
[`tools/openstates_fetch.py`](../tools/openstates_fetch.py) saved. Do not edit it by hand: the next build overwrites it.

## Where each part comes from

| Part | Source | What it gives |
|---|---|---|
| Federal list | Brennan Center for Justice, [Artificial Intelligence Legislation Tracker](https://www.brennancenter.org/our-work/research-reports/artificial-intelligence-legislation-tracker) | Which federal bills (56 from the 119th Congress, updated November 9, 2026), and the Center's category labels as topics. Its rows come from the Google Sheet its page embeds, published as CSV. |
| Federal records | U.S. Government Publishing Office, [Bill Status XML Bulk Data](https://www.govinfo.gov/bulkdata/BILLSTATUS) | For each federal bill with a number: official title, committees, introduction dates, latest action, stage. U.S. Government work, public domain, no key. |
| State bills | [Open States](https://openstates.org), which follows each legislature's own record | Our own list, below. Public-domain data, attribution requested. Needs a free API key. |
| State summaries (Illinois, New Jersey, Maryland) | Each legislature's own site | For a state bill Open States has no summary for, the legislature's own: Illinois' "Synopsis As Introduced" on the bill's status page, New Jersey's statement at the end of the introduced text, Maryland's synopsis line. Read by [`tools/state_summaries.py`](../tools/state_summaries.py) into [`content/legislation-state-summaries.json`](../content/legislation-state-summaries.json), as the legislature wrote it. |

Nothing is taken from NCSL; see "NCSL" below.

## The state list

It is our own definition, applied to the legislatures' records, and it is deliberately narrow. Three steps, then a checkbox:

1. **Found.** A full-text search of every session since 2025 in every state, DC and Puerto Rico, once for each phrase in `TERMS` in
   [`tools/openstates_fetch.py`](../tools/openstates_fetch.py): "artificial intelligence", "deepfake", "digital replica" and "synthetic media". A bill is
   found because its text says one of them. The build counts a phrase only once its search is finished in every session (`finished_terms` in
   [`tools/legislation.py`](../tools/legislation.py)): a half-finished search finds bills in the states it reached and none in the rest, and the map
   shades each state by how many bills it has, so the page would show how far the search got as if the legislatures had caused it. Where each
   phrase stands is under "Where it stands".
2. **Active.** The page's definition (introduced and not failed). A state bill is active when it became law, or when its session has not ended
   (Open States' session dates) and its latest action is not a failure, withdrawal or veto.
3. **About AI, or only mentioning it.** A bill is about AI when its title or the legislature's own summary names artificial intelligence or a close
   relative (AI, machine learning, generative, deepfake, synthetic media, digital replica, artificially or digitally generated or altered content,
   chatbot, large language model, algorithmic, automated decision, automation displacement; the list is `AI_NAMED` in the tool). The search also
   finds a school code or a resolution about Taiwan that says the phrase once. Those bills are kept, flagged `passing` in the data, and shown only
   when the checkbox "Include bills that only mention AI", under More filters, is on, where each is marked "Mentions AI only in its text". With
   it off (the default) they are in no count, no shading and no table, and the note under the table says how many more it would add.

The page says what the list is, and how many bills each rule left out, in the note under the table; the numbers come from `LEGISLATION_FEEDS.openstates`
(`found`, `included`, `passing`, `omitted`).

What a state bill carries: its official title; the legislature's own summary where it gives one (capped at 450 characters, ending in an
ellipsis when cut: Open States' abstract, or, for Illinois, New Jersey and Maryland, which it has none for, the synopsis or statement the legislature
publishes on its own site; California's is the Legislative Counsel's digest, which often opens with "Existing law"); the
legislature's subject index terms as it wrote them (minus any that only repeat the title); its latest action (Open States' own, unless that is dated in the
future, as when Georgia lists a bill's effective date as an action: then the latest action already taken, so that a bill is not sorted to the top by recency); its stage, read from the standard
classification Open States gives each action (passed by a chamber, signed or became law, referred to a committee, introduced); and a link to the
bill on the legislature's own site, or on Open States when the legislature has no page for that bill that is not generic.

### State summaries

Open States carries a legislature's own abstract for most states. For Illinois, New Jersey and Maryland it carries none, so those bills showed a dash for
a summary and their titles alone said little (Illinois' is "AI-MEANINGFUL HUMAN REVIEW"). Each of those legislatures publishes a summary of each bill on its
own site, and [`tools/state_summaries.py`](../tools/state_summaries.py) reads it, as the legislature wrote it, into
[`content/legislation-state-summaries.json`](../content/legislation-state-summaries.json) (the first 1,200 characters, with where it was read and when; the page
shows the first 450, like every state's summary). Nothing in that file is written by us: a summary made up from a title or two would be a guess, so a state
without a reader keeps its dash. `tools/legislation.py build` uses an entry only for a bill Open States has no abstract for, counts it as the legislature's own
summary when it decides whether a bill is about AI, and has the note under the table say where the summaries come from (`LEGISLATION_FEEDS.openstates.summaries`).
An Illinois synopsis is the one "As Introduced", so a bill amended since may read slightly behind; a New Jersey statement is the introduced version's.

To add a state, write a reader in `tools/state_summaries.py` (a function from a bill row to the text, what it is and where it was read, or `None`) and list it in
`READERS` and `READER_INFO`; it needs a legislature page that gives a summary in its own HTML. Many do not (Pennsylvania, Michigan, Utah and Montana pages load
their text by script or link to PDF analyses), and for those the choice is a dash or a summary we write from the bill's full text, which is a larger job: see
"Limits to know".

### Where it stands (November 12, 2026)

- **What the page shows** is the list for "artificial intelligence" alone. It found 2,042 bills; 1,258 are not active; 784 are active, of which 477
  are about AI and 307 only mention it. (The first run had 445 and 339: reading the legislatures' own summaries for Illinois and New Jersey moved 32 bills
  whose synopsis or statement names AI into the first group.) The 477 are in 38 jurisdictions (37 states or DC, and Puerto Rico; the other 14 have none),
  371 of them with the legislature's own summary. With the checkbox on, 46 jurisdictions have bills (every one but DC, Indiana, Massachusetts, Missouri,
  New Hampshire and South Dakota).
- **Summaries read from the legislatures' sites (November 12, 2026).** 208 bills gained one: Illinois 109 of 109, New Jersey 97 of 104 (the other seven,
  A 390, A 5024, A 5800, S 329, S 4888, S 4934 and S 4959, have no introduced text published yet), and Maryland 2 of 10 (its 2026 session pages answered
  with a server error that day, and a bill's page is the only place the synopsis is). Still without a summary, of the 477 bills about AI: 106 (Pennsylvania
  35, Michigan 9, Utah 7, New Jersey 6, Louisiana, Tennessee and Texas 5 each, Maryland and Montana 4 each, Arkansas, Idaho, Maine and Vermont 3 each,
  Connecticut, Mississippi and Washington 2 each, and one each in Iowa, Kansas, New Mexico, Nevada, New York, Oklahoma, Puerto Rico and West Virginia),
  and 122 of the 307 that only mention AI. Those states' pages give no summary in their own HTML, or give it in a PDF analysis or by script.
- **The other three phrases are started and not finished.** Open States' free key allows 250 requests a day, and that day's allowance (the first
  full run, the setup and the day's tests had spent most of it) ran out partway. All three phrases are finished in 14 of the 108 sessions, which
  are the seven jurisdictions Alabama, Alaska, Arizona, Arkansas, California, Colorado and Connecticut; "deepfake" also has three
  sessions searched elsewhere (Delaware, Wyoming) that found nothing new, so the build reports it as finished in 17. The build
  leaves all three phrases out until they are finished everywhere, says so when it runs, and the page's note names only "artificial
  intelligence". What the seven jurisdictions showed: 14 bills the first search had not found (Arizona 5, California 4, Arkansas 2, Alaska,
  Alabama and Colorado 1 each), 5 of them active, and 4 of those about AI (three in California, about deepfakes and digital replicas, and an
  Arkansas deepfake offense). About 280 requests remain, so two days of the free allowance; run the
  fetch again each day (see "Refreshing") and then the build.

### Limits to know

- **Narrower than NCSL's list.** Compared once with NCSL's database (below), on the list for "artificial intelligence" alone: 412 of our 445
  (93%; the list was 445 then) were also on NCSL's active list, but NCSL's has about 1,650. Three causes. The search misses bills that never say "artificial
  intelligence" (only 39% of NCSL's deepfake bills were found, and 27% of its housing bills, for example algorithmic rent pricing); the three
  extra phrases are meant to close the deepfake part of that gap, and how far they do cannot be re-measured, because nothing of NCSL's is kept.
  The "about AI" step puts bills that mention it only in passing behind the checkbox. And the active rule is stricter: NCSL still lists as pending
  many bills from sessions that have plainly ended (Hawaii, Georgia, Virginia).
- **The end of a session is the formal one.** In Massachusetts the formal session ended July 31, 2026, though committees kept acting on bills into
  October, so none of its bills shows as active; North Carolina and South Carolina are similar. In California the session's end date in Open States
  is November 30, though the last day to pass bills was in August, so its unpassed bills show as active until then.
- **Territories:** Open States covers Puerto Rico and none of the others, so Guam, the Virgin Islands, American Samoa and the Northern Mariana
  Islands have no bills here. Each state is as complete and as current as Open States' scraper for it; the `latest_bill_update` it reports per jurisdiction says how fresh.
- **To widen the list**, add a phrase to `TERMS` in `tools/openstates_fetch.py` (or pass `--term` for one run). Each phrase costs about 108
  requests, one per session, and the build ignores it until it is finished. The "about AI" step still applies.

## Federal bills

The tracker is the list; each bill's own file at GovInfo says where it stands (several files for a companion bill in both chambers, the most
advanced stage and the latest action winning). That is how a bill the tracker calls "introduced" turned out to have passed the House (H.R. 1736).
Stage is read from the actions ("Passed/agreed to in House", "Became Public Law"; any referral to a committee is "in committee"). A bill GovInfo
has no file for yet (the CLAIM Act has no number) keeps the tracker's details, and the build says so. The tracker's descriptions are its own prose
and are not copied: summaries are written by hand, in our own words, in
[`content/legislation-federal-summaries.json`](../content/legislation-federal-summaries.json), and a bill with no entry shows a dash. The
tracker sheet has one known typo (a link that begins `tps://`); the build repairs exactly that and says so. The Brennan Center's site has no
terms of use (its footer links only a privacy policy and accessibility).

## NCSL

NCSL's [Terms of Use](https://www.ncsl.org/terms-of-use) (updated May 5, 2017) say NCSL owns the material on its website and that you may not
"reproduce, duplicate or copy material from ncsl.org without permission", nor republish or redistribute it. Attribution does not stand in for
permission. The first version of the state list came from NCSL's AI Legislation Database; on 2026-11-12 the owner asked for NCSL's summaries too,
was told what the terms say, chose to leave them out, and then asked for our own list built from official records instead. So nothing of
NCSL's is in the data any more: not its list, its summaries, its subject headings or its topic tags. Linking to its database as a reference is
fine. The terms do not mention automated access. A one-off comparison against an export of NCSL's database (nothing kept from it) produced the
numbers under "Limits to know". Whether looking bills up in official records is enough on its own is a judgment, and this is not legal advice;
asking NCSL for permission remains the safe route to use anything of theirs.

## Searching, filtering and sorting the table

The bar under the Legislation toolbar (the layers, and the Show menu, which has Congress as its Federal entry: there is no Federal button) narrows
everything the page counts, which is the map's shading and legend, the hover panel, the counts and the table; the masthead keeps saying what is loaded.
Search and Sort are in view; behind "More filters" are Status, the checkbox that adds the bills that only mention AI, and the topic chips. The badge on
More filters counts what is switched on inside it (each topic picked, a status, the checkbox), and Clear filters resets all of that and the search, and
leaves the order alone. The bar is sticky, as on Papers and the Fact Bank, and the toolbar above it (the layers, the office toggle, the Show menu, Clear) sticks with it: both stay at the top of the window while the map and the tables scroll under them, and a jump to a table (the pager, the card's link) lands just below them. On the results layer only the toolbar sticks.

- **Sort.** Most recent action (the default), Oldest action, or Jurisdiction (Congress first, then the states A to Z, each with its most recently
  acted-on bill first). A bill with no last action comes after those that have one, whichever way the dates run, and a tie goes the Jurisdiction
  way. The date is the legislature's (or Congress's) latest recorded action, not the date a bill was introduced.
- **Status.** One of the stages that count as active (introduced, in committee, passed one chamber, passed both chambers, enacted: the stages of
  `LEGISLATION_STAGES` with `active` set, in that order). Each option carries the count it would leave with the search and topics applied, and one with
  nothing behind it is dimmed.
- **Include bills that only mention AI.** The checkbox for the bills described in step 3 above; its count is how many of them the search, status and topics
  leave in, and it is offered whenever the data has any such bill. It widens the list instead of narrowing it, so it changes what the page says is loaded
  (the masthead, the result line's total) rather than the result line's first number.

- **Search.** Every word typed must appear somewhere in what a row shows: bill number, jurisdiction, title, summary, status, last action, the
  legislature's subject terms, the Brennan Center's labels and the topics below. Capitals do not matter; there is a short pause after typing.
- **Topics.** Our own reading, not any legislature's or any other list's. They are defined in `LEGISLATION_TOPICS` in `data/legislation-data.js`: an
  id, a label and a list of words. The page works out each bill's topics from its own text each time it loads: a topic is assigned when one of its
  words is in the bill's **title**, or when **two different words** of it are in the bill's summary, the legislature's subject terms or the
  Brennan Center's labels (so one stray word in a long summary does not count; two words that overlap, such as "health" and "mental health" in the
  phrase "mental health", count once). A word matches at the start of a word ("employ" finds employer and employment); end it with `$` to match the
  whole word only ("rent$" finds rent, not rental). A bill can have several topics and some have none; "No topic" finds them. Chips are ANDed, as the
  Fact Bank's keyword chips are: Deepfakes and Elections leave the bills that have both. A chip's count is what choosing it would leave with the
  search and the other chips applied; a chip with nothing behind it is dimmed.
- **The list.** Nineteen topics, the places AI is used first and how it is governed after: Hiring and work; Health care and insurance; Education;
  Pricing, housing and credit; Government services; Policing and courts; Elections and political ads; Deepfakes and likeness; Chatbots and
  companions; Children and teens; Journalism, copyright and creative work; Bias and automated decisions; Privacy and data; Consumer protection and
  disclosure; Liability and accountability; Safety, security and standards; Federal preemption; Data centers and energy; Studies, task forces and
  funding. The places AI is used lead because bills are written about uses; the rest are about the technology itself or how it is governed,
  so that those bills are not left without a home. To rename one change its label, to widen or narrow it edit its words, to drop one delete its entry.
- **How well it works (November 12, 2026, the list for "artificial intelligence" alone).** Of the 533 bills the page shows by default, 475 (89%)
  have at least one topic and 58 have none; with the checkbox on, 704 of 840 do (84%) and 136 have none. (Reading the Illinois and New Jersey summaries added
  topics to bills that had only a terse title; before it was 437 of 501, and 685 of 840.) The words were checked by reading samples of
  the bills each topic found (a few false hits, for example a budget bill filed under "Studies, task forces and funding", and many bills whose title
  is only "Artificial intelligence" with no summary, which have no topic until a word in the list finds one). Counts per topic at that date are in the
  chips. The mention-only bills (the checkbox) are the noisiest, since many are omnibus budget and education-code bills.
- **Not built:** clickable topic labels in the table, and topics stored in the data (they are worked out in the page, so the generator and the
  cache do not change when the words do).

The table lists ten bills to a page (`LEG_PAGE_SIZE` in `src/js/60-legislation.js`, the owner's limit as of 2026-11-12, when it went from fifty to twenty to ten; the Papers list and the Fact Bank
keep fifty), with the pager the Papers list uses under it. Search, Status, the chips, Sort and the Show menu all start it again at page 1.

**The stats bar.** Under the Bills section's title, which is the jurisdiction and the count ("New York · 8 bills") with no word Bills of its own (taken out at the owner's request, 2026-11-12), a bar says where the bills in view stand, in the stages of the Status menu: a segment for
each stage that has some, as wide as its share of the table's width (the bar and the key share one line across the table: the key at the right, the bar filling the rest), with the count of each and its percentage of the bills in view in the key (whole numbers, each rounded on its own, so they can come to 99 to 101; under 1% shows as "<1%"). It counts exactly what the title counts, every bill the search, Status,
chips, checkbox and the state chosen leave in (not only the ten on the page showing), so its numbers add up to the title's; with none in view it is
hidden. It is worked out from the bills each time the table is drawn (`legStatsBar()`); no figure is stored or typed in.

**The card.** Each jurisdiction's card beside the map (Bills layer) holds the same stats for that jurisdiction's bills (the count, a bar and each stage's count and percentage, `legCardStats()`) and a
link, "See more details below", that pins the jurisdiction and takes the reader to its tables. It lists no bills (the owner had the previews taken out on 2026-11-12; the table below has them). The card is a hover preview, so with nothing pinned it stays on the state last pointed at for a moment after the pointer
leaves the map, and while the pointer is on it, so the link can be reached; with a state pinned it goes back to that state at once. On the 2026 Midterm results layer the card holds the state's results and the same link,
which goes to the results table.

The 2026 Midterm results table lists ten states to a page (`LEG_RESULTS_PAGE_SIZE`, the owner's limit as of 2026-11-12), alphabetically, with a pager under it; one state pinned is one row and no pager.

## Refreshing

```sh
python3 tools/openstates_fetch.py                       # every phrase in TERMS, saved to ~/.cache/ai-tracker/openstates; resumes where it stopped
python3 tools/state_summaries.py                        # the legislatures' own summaries for the bills Open States has none for (about 8 minutes the first time)
python3 tools/legislation.py build --federal-cache ~/.cache/ai-tracker/govinfo
```

then reload the page, open the Legislation tab and run `node tests/interactions.js`. `build` also takes `--brennan <csv file or address>`,
`--states-cache <folder>`, `--no-official` (skip the GovInfo lookup) and `--dry-run` (print what it would write).

- **The key.** Open States' API needs a free key (sign up at https://openstates.org, generate it on your profile). Save it, one line and nothing
  else, in `~/.openstates_key` (mode 600), or set `OPENSTATES_API_KEY`. It stays out of the repository, the cache and every log. The free key allows
  10 requests a minute and 250 a day; the fetch spaces requests 7 seconds apart, waits a minute if it is limited anyway, stops with a message when
  the day's allowance is spent, and saves every page as it arrives, so an interrupted or stopped run carries on and a finished one costs nothing to
  repeat. The whole list is about 500 requests (the 175 for "artificial intelligence" and about 330 for the other three phrases), so a first run
  takes two or three days of the free allowance, and so does a re-fetch from an empty cache (delete the folder to re-fetch). A lighter refresh, only
  the sessions still in progress, is not built. Asking Open States for a higher limit is the other way to shorten it.
- **What stops the build:** an unknown jurisdiction or session, a date that does not parse, a bad link. It writes nothing if it stops.

## On the page

`data/legislation-bills.js` is fetched the first time the Legislation tab opens (`legLoadBills` in `src/js/60-legislation.js`, through
`loadPayload` in `src/js/05-lazy.js`), so the other tabs never wait for it. It adds its rows to `LEGISLATION_DATA` and sets
`LEGISLATION_FEEDS`, which the page reads for the sources line under the map (on the Bills layer) and for the note under the table.
